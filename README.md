# Система бронирования переговорных комнат 

Frontend-приложение для поиска, бронирования и управления переговорными комнатами в различных офисах. Разработано в рамках тестового задания для стажеров Frontend (осенняя волна 2026).

## Запуск проекта

Убедитесь, что у вас установлен Node.js версии 20 или выше.

1. **Клонируйте репозиторий и перейдите в папку проекта:**
   
```bash
git clone https://github.com/talense-tasks/frontend-trainee-assignment-autumn-2026-flow-2-areallypawa-bf00542a
cd book-room
```

2. **Установите зависимости:**
В ./book-room
```bash
npm install
```

3. **Запустите проект в режиме разработки:**
в папках ./server и ./book-room:
```bash
npm run dev
```

Приложение будет доступно по адресу `http://localhost:5173` (или другому порту, указанному Vite).

## Тестирование

Проект содержит юнит-тесты, проверяющие как отдельные функции и компоненты frontend, так и бизнес-логику backend.

В частности, тестируются:

* работа с датами и временем;
* правила создания бронирований;
* проверка пересечения временных интервалов;
* создание и отмена бронирований;
* обработка конфликтов;
* отдельные UI-компоненты;

* Запуск тестов в консоли: в папке ./book-room
```bash
npm run test
```

## Архитектура и стек технологий

Приложение построено на компонентном подходе с разделением UI, серверного состояния и прикладной логики. Использование TypeScript и модульной структуры позволяет поддерживать типобезопасность и упрощает дальнейшее расширение проекта.

### Технологический стек

* **React 18** — разработка интерфейса на функциональных компонентах и Hooks.
* **TypeScript** — статическая типизация компонентов, данных и API.
* **Vite** — сборка и локальная разработка проекта.
* **React Router** — маршрутизация между страницами приложения.
* **TanStack Query** — получение, кэширование и синхронизация серверных данных.
* **Axios** — взаимодействие с REST API.
* **WebSocket** — получение обновлений расписания в реальном времени.
* **CSS Modules** — изолированные стили компонентов.
* **Vitest + React Testing Library** — тестирование компонентов и прикладной логики.

### Архитектурные принципы

**Разделение ответственности**

UI-компоненты отвечают за отображение интерфейса и обработку пользовательских событий, а прикладная логика и вспомогательные вычисления вынесены в отдельные модули. Это упрощает повторное использование кода и его тестирование.

**Компонентный подход**

Интерфейс разделён на переиспользуемые компоненты разного уровня сложности. Базовые элементы расположены в `src/components/ui/`, а из них собираются более сложные компоненты и пользовательские сценарии, например `BookingModal`, `TimeSelector` и `RoomSchedule`.

**Colocation**

Связанные с компонентом файлы располагаются рядом с ним: стили, тесты и вспомогательные модули. Это упрощает поиск файлов и внесение изменений.

**Разделение клиентского и серверного состояния**

Серверные данные управляются через TanStack Query, а локальное состояние интерфейса хранится непосредственно в компонентах и соответствующих Hooks. Обновление расписания при изменениях выполняется через WebSocket.

## Архитектура компонентов

Frontend построен на основе переиспользуемых React-компонентов. Ответственность между компонентами разделена по назначению: компоненты интерфейса отвечают преимущественно за отображение и пользовательское взаимодействие, а работа с API и бизнес-логика вынесены в отдельные модули, хуки и утилиты.

### Компоненты бронирования

#### `BookingButton`

Кнопка запуска процесса создания бронирования. Используется в различных частях интерфейса и принимает необходимые параметры для отображения и обработки действия пользователя.

#### `BookingCard`

Карточка существующего бронирования. Отображает основную информацию о встрече: название, дату, время и связанные данные.

#### `BookingDetailsModal`

Модальное окно с подробной информацией о существующем бронировании. Используется для просмотра данных встречи и выполнения доступных действий, включая отмену бронирования.

#### `BookingModal`

Основной компонент создания бронирования.

Отвечает за:

* выбор даты;
* выбор времени начала;
* выбор продолжительности;
* ввод темы встречи;
* ввод комментария;
* настройку повторяющегося бронирования;
* проверку доступности выбранного временного интервала;
* обработку ошибок при создании бронирования;
* закрытие модального окна и управление состоянием формы.

При открытии модального окна также блокируется прокрутка основной страницы.

#### `RecurringOptions`

Настройки повторяющегося бронирования внутри `BookingModal`.

Позволяет задать параметры повторения встречи и выбрать необходимые дни недели.

### Компоненты работы с датой и временем

#### `Calendar`

Интерактивный календарь для выбора даты. Поддерживает навигацию между месяцами и выбор конкретного дня.

#### `DateRangePicker`

Компонент выбора диапазона дат. Используется для фильтрации данных по периоду.

#### `TimeSelector`

Компонент выбора времени начала и продолжительности встречи.

Доступные временные интервалы формируются с учётом:

* рабочего времени переговорных комнат;
* длительности встречи;
* уже существующих бронирований;
* недоступных временных интервалов.

Это позволяет не предлагать пользователю заведомо занятые интервалы.

### Компоненты комнат

#### `RoomCard`

Карточка переговорной комнаты со сводной информацией:

* название;
* вместимость;
* расположение;
* основные характеристики.

Используется при отображении списка комнат.

#### `SmartRoomCard`

Расширенная карточка комнаты, объединяющая отображение информации о переговорной с дополнительными данными и интерактивными возможностями.

#### `RoomInfo`

Компонент подробной информации о переговорной комнате. Используется на странице конкретной комнаты и отображает её характеристики и доступное оборудование.

#### `RoomSchedule`

Компонент отображения расписания конкретной переговорной комнаты.

Представляет занятость комнаты в виде временной шкалы и позволяет пользователю определить свободные интервалы для бронирования.

### Дополнительные компоненты

#### `ExportIcsButton`

Компонент экспорта созданного бронирования в календарный формат `.ics`. Позволяет скачать событие и импортировать его в совместимые календарные приложения.

#### `Toasts` / `SuccessToast`

Система уведомлений пользователя о результате операций.

Используется, например, для отображения успешного создания или отмены бронирования, а также сообщений об ошибках.

#### `ui/`

Набор базовых переиспользуемых UI-компонентов. Включает элементы управления, выпадающие списки, иконки и другие компоненты, используемые в различных частях приложения.

## Работа с real-time данными

Для обновления расписания без необходимости ручного обновления страницы используется WebSocket-соединение.

При изменении данных сервер отправляет событие клиенту. Frontend обрабатывает событие и инициирует получение актуальных данных, благодаря чему открытое расписание остаётся синхронизированным с сервером.

Такой подход позволяет не дублировать серверное состояние на клиенте и получать актуальные данные после изменений бронирований.

При потере соединения предусмотрено восстановление подключения и повторная синхронизация данных.
